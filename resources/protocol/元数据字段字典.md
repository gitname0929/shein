# 元数据字段字典

用于组织方构造样本、参赛者理解输入。字段位于任务的 metadata 对象，另有说明的除外。仅提供与当前规则相关的字段；缺失或 null 表示未知，不默认取 false、0 或空字符串。无关字段不改变结论。

下表“类型”描述规范输入。某条原文明示了非法申报值的处理时，专门的非法值样本可保留原始值，并由组织方在样本说明中标注为刻意设置的输入异常。不能因预先清洗而移除这类考核单元。

## 1. 通用任务字段（任务顶层）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| audit_unit_id | string | 冻结审核单元的唯一键；不能由预测结果生成。 |
| sample_id | string | 样本键，可被不同规则或版本复用。 |
| rule_id / rule_version | string | 明确选择的规则与版本。 |
| review_date | string | YYYY-MM-DD；不使用本机日期替代。 |
| materials | array | 材料元数据与相对路径，结构见 input.schema.json。 |

## 2. 原文中显式命名的申报字段

| 字段 | 类型 | 含义或示例 |
| --- | --- | --- |
| market | string | 虚构市场，例如 Q、Q1、Q2。 |
| category | string | 原文明示类别，例如桌面灯、组合支架。 |
| power_mode | string | 原文明示供电方式，例如可充电。 |
| declared_model | string | 申报主型号；按总则做型号比较。 |
| old_model | string | 原件使用的旧型号，不等同于任意别名。 |
| declared_bundle_model | string | 零售套装的整体型号。 |
| declared_component_models | array of string | 申报组件型号清单；集合含义按原文。 |
| declared_host_model | string | 申报兼容的主机型号。 |
| declared_generation | integer | 明确申报的代次数值。 |
| declared_color_name | string | 颜色版本名称；无需推断现实颜色命名。 |
| declared_sizes | array of string | 尺寸版本清单，大小写按原文。 |
| declared_detachable | boolean | 配件是否可拆卸。 |
| declared_quantity | integer | 申报数量；合法范围按原文。 |
| declared_min_age | integer | 虚构练习文案使用的年龄下限。 |
| declared_capacity_ml | number | 申报容量，单位 mL。 |
| declared_height_cm | number | 申报可调高度，单位 cm。 |
| declared_length_mm / declared_width_mm / declared_height_mm | number | 长、宽、高三个角色独立，单位 mm。 |
| package_longest_edge_mm | number | 包装最长边，单位 mm；不从照片估算。 |
| declared_use | string | 申报用途文案，使用总则文本比较。 |
| required_document_version | string | 本任务指定文件版本，不自行换成新版本。 |
| language_mode | string | 中文、英文或双语；取值与原文一致。 |
| required_faces | array of string | 规定检查面 ID，例如 front、back。 |
| opening_face | string | 开启面 ID，应能关联到材料上下文。 |
| is_accessory / sold_separately | boolean | 是否配件、是否独立销售，两个条件分别保留。R009 的独立销售条件使用 scenario.independent_sale。 |
| reusable_case | boolean | 是否采用原文明示的可重复使用收纳盒。 |
| target_field | string | 本任务待核验的目标字段名称，例如型号、材料编号；用于 R005 判断补充视图是否对应同一字段。 |
| image_color_mode | string | 任务给出的图片颜色模式，例如 grayscale 表示黑白照片；未提供时按图片可见内容判断。用于 R028。 |

## 3. 原文使用中文描述的输入上下文

为避免自行猜测上下文，组织方在 metadata 中使用以下统一结构。它们提供输入条件，不直接给出图片内审核字段的识别答案。

| 字段 | 结构 | 用途 |
| --- | --- | --- |
| scenario | object | has_outer_package、is_single_pack、is_multi_pack、is_mixed_size_set、is_magnetic_component、has_powered_base、is_practice_box、uses_tag（是否使用附签承载审核字段，R004）、independent_sale（是否申报独立销售，R009）等布尔属性；仅在相关规则需要时提供。 |
| scenario 声明值 | object | can_disassemble_in_storage、one_item_per_use 为布尔值；declared_mark_type、declared_color_version、declared_state 为字符串，用于原文明确的场景触发。 |
| declared_components | array of object | 每项含 component_id、model，可含独立销售声明；component_id 对应原文组件键。 |
| declared_material_number | string | 任务申报的材料编号，用于 R049 等跨源比较。 |
| expected_page_count | integer | 文件规定总页数 N，不从已收到文件数量推断。 |
| withdrawal_date | string or null | 任务提供的撤回日，合法性与时间关系按 R048。 |
| production_date | string or null | 任务指定的生产日；原文要求读包装生产日时仍以图像证据为准。 |
| exception_list | array of object | 每项含 sample_id、exception_rule_id；后者与当前规则 ID 精确匹配才具有引用关系。 |
| material_context | object keyed by material_id | 为各材料提供 face_id、component_id、source_type（photo/design/render/unknown）、is_standard_front_view、document_id。 |
| opening_edges / opening_cut_lines | array of object | 每项含 material_id、两个归一化端点 [x,y]；用于原文要求由任务标记的开启边或开封切线。 |
| designated_regions | array of object | 每项含 material_id、region_name、bbox；仅用于原文要求由任务指定的区域，例如确认人区域。 |

证明文件内的型号、编号、有效期、签发日、清单以及图像中的警示/图形，应由材料提取，不能在 metadata 中预先泄露识别答案。task 提供的 contextual 字段与可见内容不一致时，按对应规则及总则处理。

图片边框、标准正视图、材质层次等未由任务明确指定的视觉事实，仍应由系统识别。某条规则需要的场景条件未提供时，记录缺失条件；不得依靠真实行业常识补成新要求。

page_index定位材料的源文件页，与图片内印刷的证明页码不同。R003按可见印刷页码核验覆盖，不能将单张PNG源页号当作证明页码。
