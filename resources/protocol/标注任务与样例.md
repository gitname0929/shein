# 标注任务与评分口径

annotate同时读取审核任务INPUT_JSONL及标注目标TARGETS_JSONL。审核任务沿用input.schema.json；每个标注目标满足annotation_task.schema.json。正式目标均为文本或null，不提供期望值、标签或答案框。

目标字段为annotation_id、audit_unit_id、material_id、page_index、target、value_type、normalization、bbox_format。target给出提取指令和是否包含字段名；page_index是源材料页码。value_type固定string_or_null，normalization为unicode_nfkc_strip，bbox_format为normalized_xyxy。三个标识和页码由输入原样回传。

输出仍为annotation.schema.json中的8个字段。value只提取target指定内容：要求完整字段行时须含字段名，要求矩阵单元时仅输出图例对应的单元状态文字。无需猜测被遮挡的内容。status=value表示目标值可读且合法；unreadable表示目标不可读，此时value必须JSON null；invalid_value表示可读目标本身违反明确格式或取值约定。另一字段违规不自动把本目标status变为invalid_value。

label是指定审核规则在该审核单元全部材料下的结论，不是仅该标注文本是否正确。bbox是目标行/对象或其遮挡区域的[x1,y1,x2,y2]，按整张源图宽高归一化至0至1，x1<x2、y1<y2。页码和坐标不得使用布尔值。

评分双方对字符串先Unicode NFKC归一化，再strip首尾空白；之后内部字符、标点、空格及大小写必须一致。例：“型号：ＡＢ-１”与“型号:AB-1”等价；“AB-1”与“ab1”在标注值中不等价。业务规则中的型号忽略大小写等约定用于业务比较，不扩大文字标注的容错范围。JSON类型严格区分，数字、字符串、布尔值及null不相互转换。

每个目标须值、类型、status、label、材料、源页码和IoU≥0.5同时正确，得分7×正确目标数/42。缺失、重复或错误目标不计分；输出失败可在额外错误文件记录，不能伪造unreadable或答案。

03_公开开发集/标注样例提供3个目标：清晰字段行、遮挡不可读、可读但编号非法。材料复用公开审核样例，不增加正式题量；参考值与归一化后的参考值均应得7/7。这是评分算术样例，不是参赛系统满分实现。

从学生包根目录运行：

```sh
python3 02_协议与评分/校验工具/validate_annotations.py --inputs 03_公开开发集/标注样例/inputs/tasks.jsonl --targets 03_公开开发集/标注样例/inputs/targets.jsonl --predictions 03_公开开发集/标注样例/reference_annotations_nfkc.jsonl --references 03_公开开发集/标注样例/references/annotation_gold.jsonl
```
